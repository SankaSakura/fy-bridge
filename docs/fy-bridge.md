# API 与技术说明

安装和日常操作请先看 [README](../README.md)。本文说明客户端可以发送什么，以及服务如何处理请求。

## 连接参数

- 默认 Base URL：`http://127.0.0.1:43119/v1`。
- 模型名：`fy-current`。它代表“使用当前 FY 专用卡的模型”，不是 FY 上某个模型的正式名称。
- 认证：请求头 `Authorization: Bearer <API 密钥>`，密钥从扩展设置页复制。
- 默认请求超时：180 秒；建议客户端等待至少 210 秒。

公开接口为 `GET /v1/models` 和 `POST /v1/chat/completions`，也保留不带 `/v1` 的路径。服务只绑定 `127.0.0.1`，不向普通网页开放 CORS。`/bridge/*` 供扩展内部使用，不作为客户端接入接口。

## 消息与参数

示例请求体：

```json
{
  "model": "fy-current",
  "messages": [
    { "role": "system", "content": "请用简洁的中文回答。" },
    { "role": "user", "content": "你好。" }
  ],
  "stream": false
}
```

支持的顶层字段：

| 字段 | 说明 |
| --- | --- |
| `model` | 填写 `fy-current`；保留旧名 `aifun-current` 仅用于兼容升级前的客户端配置 |
| `messages` | 1—2000 条消息，每条只包含 `role` 与字符串 `content` |
| `stream` | 可选布尔值，默认 `false` |
| `n` | 可选，只允许 `1` |
| `stream_options` | 可选，只支持布尔字段 `include_usage` |
| `max_tokens` | 可选正安全整数；映射到 FY `model.completion_params.max_tokens`，受当前模型 `parameter_ranges.max_token` 的支持标记与范围约束 |
| `temperature` | 可选 0—2 数字；映射到对应 completion 参数，再按模型范围检查 |
| `top_p` | 可选 0—1 数字；映射到对应 completion 参数，再按模型范围检查 |

`system` 消息必须连续放在开头，后面可以包含 `user` 和 `assistant` 历史消息；最后一条必须是非空 `user`。不支持 `developer`、`tool`、工具调用、多模态内容，以及表格外的额外参数（包括尚未接入的 `stop`、`max_completion_tokens` 等）。可选生成参数为 null 时视为未指定；数字类型错误返回 400，并在 error.param 中标明字段。未知字段仍返回 400，不会悄悄忽略。

所有开头的系统消息合并后写入 FY 的主提示词；没有系统内容时写入一个空格。只有当前用户消息时，直接发送其内容；有历史时，将原顺序的历史和当前输入放入 `FY_CONTEXT_V1` JSON 文本后作为玩家输入发送。因此历史中的角色是文本标记，不等同于 FY 的原生角色历史。

请求体最大 2 MiB。网站自身还可能有更小的长度限制，工具不会自动截断上下文。

## 返回结果与排队

非流式返回 Chat Completions JSON，内容位于 `choices[0].message.content`。流式请求在生成和配置恢复完成后发送 SSE，以 `[DONE]` 结束；不提供实时 token 流。`finish_reason` 支持 `stop`、`length` 和 `content_filter`。FY 的点数不是模型 token 数，因此 `usage` 为 `null`。

一次只在 FY 执行一个请求，最多另有 8 个请求排队。停止反代会取消当前请求，并让尚未发送的排队请求返回停止错误；不会自动重发这些请求。

| HTTP 状态 | 常见原因 |
| --- | --- |
| 400 | 模型名、消息格式或参数不受支持 |
| 401 | API 密钥不正确 |
| 409 | 尚未选择专用卡，或有其他连接占用 |
| 413 | 请求体过大 |
| 423 | 上次任务的配置尚未恢复 |
| 429 | 等待队列已满 |
| 502 | FY 生成失败、回复格式变化或浏览器任务失联 |
| 503 | 反代未连接、正在停止，或排队请求被停止 |
| 504 | 请求超时或客户端已取消 |

## 配置、会话与恢复

每次任务会先备份专用卡配置，再临时写入系统指令，将记忆设为 0，并清空额外前后置词、世界书、正则、摘要和记忆宫殿，关闭自动生图。生成前会读取 FY 的提示词调试结果，确认系统提示词和记忆符合要求；不符合时不会开始生成。

指定上述生成参数时，也会备份完整模型配置，查询 FY 当前模型能力，临时合并显式参数，并在回读确认保存后才开始生成。未指定的参数继续沿用 FY 原值；不替换模型。任务结束后恢复原模型与参数配置，再返回回复。如果运行中检测到人工修改，不会直接覆盖，而是保留备份并提示手动恢复。正常处理期间的临时备份不会显示为异常。

通过 FY 当前选择的会话 ID 继续对话；在“新对话”状态下，首个请求创建会话并保存返回的 ID，后续复用。记忆始终为 0，完整上下文由客户端提供。任务期间不要手动切换会话。

超时、取消、网络断开和浏览器崩溃均不自动重发。本地取消无法保证网站已经开始的生成立即停止；重新提交前应先确认是否已有结果。

## 本地文件与浏览器后台

扩展通过 `local.fy.bridge` Native Messaging 主机启动本地服务，并保持扩展后台运行。设置页不承担任务执行，所以可以关闭；浏览器和 FY 专用卡标签仍需保留。点击“停止反代”后保存停止意图，下次启动浏览器也不会自行开启，直到用户再次点击“启动反代”。

扩展的 `chrome.storage.local` 保存连接地址、密钥、专用卡、自动续接状态和未恢复的原配置，不保存待执行请求队列或回复，不同步到云端，也不导出 FY Cookie。

回复流中的空 `data:` 按空事件忽略。非空数据无法解析时仍返回失败，不将部分正文当作完整回复，也不重发。为便于定位，扩展在 `chrome.storage.session` 的 `lastStreamFailure` 中额外保留最近一次解析失败的任务 ID、会话 ID、事件位置、正文字符数、最多 65536 字符的部分正文和最多 512 字符的异常数据。该摘要只保存在本次浏览器会话内，可在扩展后台开发者工具中读取，关闭浏览器后清除；完整原始数据另外写入下述后台文件日志。

`.local/fy-bridge/token.txt` 保存首次运行时用 32 字节安全随机数生成的密钥，后续复用；`connection.txt` 是本机连接信息副本，`native-start.log` 记录服务启动信息。`.local/native-messaging/` 保存安装器生成的启动程序和浏览器登记文件。请勿将 `.local/` 随源码分发。旧 `.local/aifun-bridge/` 的密钥会迁移到当前数据目录。

## FY 请求与响应日志

后台默认把每次客户端请求以及反代发往 FY、从 FY 收到的数据追加到 `.local/fy-bridge/logs/fy-traffic-YYYY-MM-DD.log`，日期按北京时间划分。无需打开设置页，没有新增界面或按钮。更新后需停止旧服务、重新加载扩展并重新启动反代，服务和扩展必须一起更新。

日志是 UTF-8 JSON Lines（每行一条 JSON），保留完整业务正文，不以诊断摘要代替原始数据。记录聊天生成、提示词调试、配置读取、临时配置写入和原配置恢复。请求在发送前记录，响应按接收顺序、在任何 JSON/SSE 解析之前分段落盘，所以无法解析的数据和 HTTP 错误响应正文也会保留。不会记录 Cookie、Authorization 或本地 API 密钥；记录的请求头仅含反代主动设置的业务头，响应头仅含内容类型、长度、编码、日期及请求 ID。

| 记录 | 内容 |
| --- | --- |
| `client_request` | 客户端传入的完整消息对象，以及转换后的系统提示词和玩家输入 |
| `request` | FY 接口路径、方法、请求头和实际序列化的完整请求正文；表示一次发送尝试 |
| `response_headers` | FY 的 HTTP 状态与上述响应头 |
| `response_chunk` | 原始响应片段的 UTF-8 文本、原始字节的 Base64、字节偏移及分段序号 |
| `response_end` | 是否接收完整、接收字节数、解码尾部文本及读取错误 |
| `transport_error` | 网络错误、超时或取消信息 |
| `bridge_result` | 扩展交回的完整结果、错误和配置恢复状态 |

用 `jobId` 关联同一客户端任务，`captureId` 关联一次页面操作，`exchangeId` 关联一次 FY HTTP 请求。初次连接和手动配置恢复不属于生成任务，`jobId` 可以为空。按同一 `exchangeId` 的 `chunkNumber` 顺序拼接 `response_chunk.text`，再追加 `response_end.decoderTail`，可还原解析器收到的全文；逐段解码并拼接 `base64` 可还原浏览器交付的响应体字节（HTTP 解压后、文本解码前，不含 TLS 或 HTTP 分块封装）。

网络中断、超过现有 8 MiB 接收上限、关闭页面或进程崩溃时，只能保留已经收到并写入的部分；`complete: false` 或缺少 `response_end` 表示响应未确认完整。写盘或日志通道失败会在后台控制台记录，生成不会因此自动重发；该次页面操作停止继续写入，返回结果附带 `trafficLogIncomplete`。日志不自动删除、不自动上传、不随仓库提交，长期使用会占用磁盘空间，其中包含完整提示词、历史、回复和卡片配置，应按私人对话资料保管。

## 手动运行与开发

本项目使用 Node.js 内置模块，不需要 `npm install`。安装浏览器启动器后，可以通过 `手动启动服务.cmd` 运行服务，或直接执行：

```powershell
node .\server.mjs --port 43119 --timeout-seconds 180
```

可选 `--app-id` 指定初始卡片 UUID，扩展连接时仍会按所选专用卡配置。默认不设置 Windows 开机自启。手动服务在原终端按 Ctrl+C 结束；扩展只自动关闭由浏览器启动器管理的服务。

FY 网站接口与浏览器页面可能变化。出现不支持的配置、调试或回复结构时，工具会返回错误，避免使用未经确认的内容继续生成。


## 生成参数的真实转交与恢复（2026-10-19）

设计依据来自 FY 当前公开前端：[模型参数编辑与保存](https://aifun.wiki/_next/static/chunks/2hax7qnjai8s6.js)、[模型能力与列表转换](https://aifun.wiki/_next/static/chunks/2xzg-hxpr7hh1.js)、[参数字段映射](https://aifun.wiki/_next/static/chunks/30cq5i_mps4kz.js)。具体版本源码已只读保存到本地 `AIRP-local/evidence/fy-parameters-2026-10-19`；这些是公开实现依据，不是行为验收证据。未登录的公开脚本与既有请求日志均表明模型配置包含 `model.completion_params`，并不意味着每个 FY 模型都会使用全部参数。

链路为客户端参数 → 本地 protocol 验证 → 排队任务 generation → 扩展后台 → 页面完整配置备份 → GET `/go/api/workspaces/model-list` → 根据 `provider_name/model_id` 精确定位当前模型 → 检查 `parameter_ranges` → POST `/go/api/apps/config` 写入 `model.completion_params` → 完整回读确认 → 生成 → 恢复并确认原配置 → 返回。参数、原值、临时写入和恢复均可在既有请求日志中定位。没有往提示词塞“最多输出多少字”，也没有在本地截断正文伪装 token 上限。

- max_tokens 对应模型范围键 max_token；temperature/top_p 使用同名范围。仅接受 supported=true、数值有限且合法的 min/max。缺少能力资料、出现重复模型身份、模型不支持或超范围时，生成前失败；不自动换模型、夹紧参数、忽略设置或重发。
- 官网 step 是滑块刻度；没有后端证据表明所有 API 数字必须对齐该刻度，因此不额外引入步长拒绝。max_tokens 仍必须是整数。
- 只覆盖明确传入的三个参数；其他原参数、提供商、模型名称等保持。整个 model 对象随备份和恢复，completion_params 原来为空对象时也按原样恢复。
- 旧恢复备份未包含 model 时，恢复只投影旧字段，不补造模型数据；不会因为更新而覆盖旧备份范围外的模型。新任务含参数但旧页面适配器未备份模型时，生成前拒绝。
- 查询能力可能耗时，所以保存参数前再次确认会话和原配置未改变。保存后的回读不一致或恢复冲突不宣称成功，保留备份和原有人工恢复入口。
- 服务通过 X-FY-Generation-Parameters:1 确认扩展支持参数链路；页面 prepare 也返回 generationProtocol:1，成功结果回传实际确认过的参数。服务与扩展只更新一侧时，不会静默忽略传入参数。旧的无参数请求仍保持原链路。
- 不能证明上游模型内部真的按参数采样，也不能在不运行模型的限制下承诺输出一定恰好达限。这里实现的是依据 FY 自身能力声明的真实配置转交和回读保护；实际行为尚未执行。

### 对“接收但不生效”的取舍

不作为默认行为。max_tokens 通常用于控制输出预算；只接收却忽略会使客户端误判长度/用量边界，也无法把本地截字等同于模型 token 限制。如果将来确有不支持这些参数的模型需要兼容，应另行明确启用宽松模式，逐次记录被忽略字段并向使用者说明限制，不能把它列为真实参数支持。本轮已有真实配置入口，因此没有实施静默忽略或默认宽松模式。

### 源码质询与限制

1. 修好 max_tokens 后会不会又因作者 temperature 失败？同时实现 temperature/top_p，分别按该模型能力检查，不写死提供商名单。
2. 新服务接旧扩展会不会表面成功、实际忽略？请求前版本协商与完成后参数确认双重阻挡。
3. 是否把整个模型对象只做浅引用，导致原备份也被改？读取时 structuredClone，合并时分别新建 model/completion_params；备份不被覆盖。
4. 是否破坏旧恢复数据？是否含 model 由备份自身决定；无参数任务仍不扩大配置写入范围。
5. 上游不支持是否偷偷退化？没有；缺少能力资料、参数非法、回读/恢复异常均保持失败，不自动重发。
6. 本轮未运行测试、哈希、应用/扩展流程、模型请求或真实 FY 配置写入。项目为直接执行的 Node/扩展源码，无新增转译构建；未用语法检查或其他名称绕过禁止测试的限制。
